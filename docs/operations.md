# 运行维护与部署说明

## 本地运行

工作目录为仓库内的 `faretrace/`；启动命令与虚拟环境设置见[项目首页](../README.md#快速运行)。默认服务只监听 `127.0.0.1:8000`。

- `GET /api/health`：验证应用可响应并返回配置版本；不是完整数据库或外部地图服务探测。
- `GET /api/config`：核对当前进程加载的配置。配置有进程级缓存，修改后重启。
- `python seed.py` / `POST /api/demo/reset`：删除并重建演示数据。仅在可丢弃数据库上执行。
- `FARETRACE_SEED_ON_START=0`：关闭启动时灌种子；默认开启，且只在库为空时灌入。

应用业务时间使用沈阳本地时间 UTC+8，以 naive datetime 存储。不要把带时区的外部订单直接混入演示数据口径。

## 演示部署材料

`faretrace/deploy/` 包含打包脚本、Nginx 配置、systemd 单元和 Linux 安装脚本，用于独立演示主机。仓库中存在脚本不代表已在本次维护中完成服务器部署或验证。

安装脚本以 root 权限安装系统包、创建服务用户、向 `/opt/faretrace` 复制应用并启动服务。它还会替换部分 Nginx 默认配置、删除默认站点并尝试放行 HTTP / HTTPS 端口，因此应先完整审阅脚本，在独立主机测试，不能直接用于已有业务服务器。

默认 Nginx 配置是 HTTP 反向代理；放行 443 端口不等于已配置 TLS。需要自行配置域名、证书、访问边界与网络策略。

## 生产化前置工作

| 当前行为 | 上线前需要的改造 |
| --- | --- |
| 无身份认证与订单授权 | 增加身份认证、角色权限、订单级资源检查；乘客 / 司机视角不等于权限隔离 |
| `POST /api/demo/reset` 默认开放 | 从生产路由移除或受严格管理权限保护 |
| SQLite `synchronous=OFF`、`journal_mode=MEMORY` | 重新设计耐久性参数；按负载选择持久化方案并验证故障恢复 |
| `create_all` / `drop_all` 管理结构 | 引入可审阅的迁移与回滚流程；升级不能靠清库完成 |
| 业务写入未提供请求级幂等键 | 为外部集成、Agent 提交和自动重试设计幂等与冲突处理 |
| 无完整可观测性与容量指标 | 增加请求追踪、结构化脱敏日志、错误率、延迟和资源监控 |
| 无生产备份与恢复演练 | 建立一致性备份、保留策略和实际恢复验证 |
| 公开瓦片 / 路由服务用于演示 | 核查服务政策、配额、归属标记与数据授权，选择适合负载的服务 |

## 常见问题

| 现象 | 排查方法 |
| --- | --- |
| `ModuleNotFoundError: app` | 在 `faretrace/` 下运行，并确认使用正确虚拟环境 |
| 依赖版本冲突 | 新建虚拟环境后重新安装；不要依赖系统 Python 的其他项目包 |
| 订单列表为空 | 确认种子开关与数据库地址；只在允许丢失数据时运行重置命令 |
| 地图底图不显示 | 检查瓦片联网；本地 Leaflet 资源与已有矢量图层不依赖 CDN |
| 配置文件缺失 / 改动未生效 | 检查 `FARETRACE_CONFIG` 指向的文件，修改后重启进程 |
| 轨迹缺失或残差提示 | 这是业务降级结果；查看 attribution 的 `quality_flags`、`residual` 与证据，不应通过改写费用隐藏问题 |
| CI 与本机结果不同 | 比较 Python / 依赖版本、是否遗漏未跟踪文件，以及是否使用干净环境 |

当前配置的残差提示阈值与状态阈值不同：绝对值超过 0.01 元会提示待核查；超过 1.00 元才将整体状态设为 `NEEDS_REVIEW`。轨迹质量不足也可能使整体状态为 `DEGRADED`。
