## 台词蓝本

### CEO（0:00–2:00）
> "各位好。上周我在平台打了个车，预估价 18 元，实付 27 元。我多付了 9 块钱，但我不知道这 9 块钱是堵车、绕路，还是计价规则变了——司机也说不清，客服只有一句话：'系统按实际里程和时长计算'。消委会的调查也发现，不少订单实际用时明显大于预计用时（Guangdong Consumers Council, 2024）。今天我们带来的方案 FareTrace，不是做一个更准的预估价，而是做一个订单完成后的**差额归因层**：把'多付的 9 块钱'拆开，每一分钱配上证据。请 CFO 先讲可行性。"

### CFO（2:00–5:00）
> "从 TELOS 五个维度看：技术上，四路数据——预估快照、实付账单、轨迹、参考路径——平台本来就都有，我们只做读取和解释；经济上，开发约 18 人日，运行是单机 SQLite 零成本，收益主要是客服争议处理效率与投诉率下降；法律上，演示数据全部合成、不含个人信息，且账单可追溯恰好呼应交通部新规的监管要求（Ministry of Transport, 2023）；运营上，系统不替代计价、不接支付，只是在订单完成后追加一步计算，对现有流程侵入极小；进度上，五个阶段、每阶段测试全绿再推进，第 13 周截止前可交付。结论：五个维度全部可行。接下来请 CIO 讲我们是怎么实现的。"

### CIO（5:00–9:00）
> "系统三层。接口层是 FastAPI：订单接入、完单即归因、双视角账单、争议四个资源；服务层是领域核心——geo 做轨迹到参考路径的投影，trajectory 做去重、剔异常、拟合度和拥堵段识别，pricing 用 Decimal 做计价求值，attribution 是核心算法：距离偏差、时间偏差、价格规则差异三个维度，拆成六个归因项加残差；数据层 11 张表，金额一律两位小数 Decimal，归因记录里落了 config_version、算法版本和 revision，口径可追溯。两个设计决策请记住：**残差永不并入其它项**——解释不了就明说；**争议发起即冻结快照**——之后重算不影响证据。下面用真实的演示数据跑一遍。"

### 数据/算法工程师（9:00–14:00，现场演示）
1. "这是订单 FT-1800，预估价 18 元，实付 27 元，差额 9 元——就是我们 CEO 那单。"（切到 `/orders/FT-1800/bill`）
2. "乘客视角：路径偏离 +3.10 元——拟合度只有 0.33，平均偏离 67 米，账单里程比预估多 2 公里；拥堵延迟 +4.20 元——840 秒连续低速，低于 15 公里每小时；计价规则变化 +1.70 元——起步价从 4.56 涨到 6.26。三项合计正好 9.00 元，残差 0。每一项都可以展开看证据 JSON：时间段、轨迹片段、阈值、字段对比都在里面。"
3. "切到司机视角：同一份归因，重新叙述——与驾驶行为相关 3.10 元，与路况相关 4.20 元，与平台规则相关 1.70 元。司机能看清哪些钱跟自己有关。系统不做裁决，只做结构化呈现。"
4. "现在司机不服，对路径偏离发起争议。提交的瞬间，系统把整份账单和证据**冻结**成快照——我们当场重算一次归因，revision 变了，但争议快照里的金额和证据一个字都没变。运营复核后流转到 RESOLVED。"
5. "再看一个降级案例 FT-1005：轨迹缺失，页面明确提示'本次账单基于不完整轨迹生成'，拥堵记 0、正时长按降级口径计入司机延迟，还有 0.20 元解释不了的差额——显示为残差，绝不藏起来。"

### 项目经理（14:00–15:00）
> "总结三点：第一，乘客和司机看到的是**同一份数字、两种叙述**，这就是双向透明；第二，金额守恒有自动化测试背书，36 组随机订单全部通过；第三，所有阈值集中在配置文件里，可查询可追溯。局限也说清楚：偏离判定基于直线距离，不能区分合理绕行，所以结论定位是'待复核证据'。谢谢，欢迎提问。"

## Q&A 预答清单

| 可能问题 | 要点回答 |
|---|---|
| GPS 漂移会不会误判绕路？ | 会，所以我们用拟合度门控 + 偏离段证据呈现，不做"绕路"定性；60 秒拥堵下限也是同一逻辑——宁可保守并留证据。 |
| 轨迹缺失时为什么拥堵记 0？ | 没有速度证据就不能说"堵车"。正时长全部进入司机延迟是降级口径，已在 ASSUMPTIONS.md 明示，页面有降级横幅，运营可复核。 |
| 残差 0.20 元是怎么来的？ | 实付总额与账单分项之和的差异（账单存在未列明调整）。残差证据里会拆成快照差/账单差/其它三部分。 |
| 金额为什么不会差 1 分钱？ | 全程 Decimal + ROUND_HALF_UP，守恒容差 ±0.01 元，36 组随机订单 + 六笔种子全部通过断言。 |
| 为什么不接真实地图？ | 课程演示要求离线可运行、数据可复现；参考路径折线 + 局部平面投影在城市尺度误差 < 0.5%，真实落地再换路网服务。 |
| 怎么保证乘客和司机看到的一样？ | 双视角是**同一份归因的两个投影**（bill_view.py），数字必然一致，只差叙述分组。 |
| 能扩展什么？ | 路网级偏离（区分封路/禁左）、真实路况源、归因记录防篡改存储、预估价模型反哺。 |
| 团队怎么协作的？ | 六角色分工（TEAM_ROLES.md），五阶段推进，每阶段 pytest 全绿才进下一阶段，共 73 项自动化测试。 |

## 术语表（专业术语准确性 /2.5）

| 术语 | 英文 | 定义 |
|---|---|---|
| 预估价快照 | estimate snapshot | 下单时冻结的报价及计价参数 |
| 差额归因 | fare delta attribution | 把实付−预估的差额拆解为可解释业务因子 |
| 拟合度 | fit score | 轨迹对参考路径的平均贴合程度（0–1） |
| 拥堵延迟 | congestion delay | 速度低于阈值且持续超阈值的时段折算金额 |
| 残差 | residual | 无法归因的差额，显式保留不并入其它项 |
| 证据快照 | evidence snapshot | 争议发起时冻结的账单与证据副本 |
| 口径版本 | config version | 阈值与规则的版本标识，落入归因记录 |
| 数据质量标记 | data quality flag | 轨迹缺失/缺口/去重/剔异常等降级留痕 |
