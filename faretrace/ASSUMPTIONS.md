# ASSUMPTIONS.md — 技术假设与边界声明（沈阳版）

> 需求未明确处，以本文件与 `config/attribution.yaml` 为准。
> 当前口径：`config_version = cfg-sy-1.0.0`、`algorithm_version = faretrace-sy-attr-1.0.0`

## 0. 数据真实性声明（最重要）

1. 全部订单、账单、轨迹为**合成数据**，但**道路几何基于沈阳真实地名锚点**（OpenStreetMap 公开数据的近似坐标，见 `app/services/shenyang.py` 的 `ANCHORS`：沈阳北站、市府广场、青年大街沿线各路口、浑河桥、三好街、沈阳站、中街、北陵公园、浑南西路、沈阳南站、苏家屯等 21 个锚点）。轨迹沿锚点折线插值生成，非随机直线。
2. 锚点坐标为近似值（±数十米级），仅用于课程演示，不用于真实导航。
3. 不接入真实支付、付费地图 API、真实出租车计价器；OSM 瓦片为免费服务。
4. 引用沈阳计价规则与公开调查使用哈佛引用格式占位（见 `docs/references.md`）。

## 1. 沈阳计费基准口径假设（关键！）

| 编号 | 假设 |
|---|---|
| F1 | 计费基准为固定规则（起步价 9 元/3km 白天、10 元/3km 夜间；里程 500m/1 元、夜间 455m/1 元；阶梯返空 15–20km×30%、>20km×50%；等候费高峰 120 秒/元、平峰 180 秒/元），字段全部来自 `config/attribution.yaml`，代码零魔法数字 |
| F2 | 里程运价"每 500 米加收 1 元"实现为**超出 3 公里部分按 500 米向上取整**（ceil）：3001 米即按 500 米档收 1 元。夜间同理按 455 米取整 |
| F3 | 阶梯返空费按**里程分段**计算：15–20 公里部分运价×30%，20 公里以上部分运价×50%（非全额累进）。运价取对应档位连续费率（白天 2 元/公里、夜间 1000/455 元/公里） |
| F4 | 等候费按时距并计：低速（<12km/h）期间里程费照常计入里程，等候费另收；**每个等候事件的高速/平峰秒数按高峰窗口边界切分**（07:00–09:00、16:30–18:30），高峰秒/120 + 平峰秒/180，逐事件结算后求和 |
| F5 | "夏季使用冷气"按夜间档参数处理（演示数据未区分季节）；真实落地需按月份/空调开关判定 |
| F6 | 计价档位（白天/夜间）按**上车时间**判定预估档、按**行程结束时间**判定实付档——因此跨 22:00 的订单会产生合法的"夜间/冷气档差价"归因项（SY-1004 即此场景）。真实计价器通常按上车时刻判定，演示口径已在证据中明示 |
| F7 | "计价规则变化"在沈阳固定基准下**恒为 0 元**，作为账单上恒输出项，证据中列出完整规则字段以满足"固定基准可追溯"要求 |
| F8 | 预估价快照按"预估里程 + 预估档费率、无等候"构造（真实平台预估通常不含等候费与返空费，本系统同口径） |

## 2. 地图与轨迹假设

| 编号 | 假设 |
|---|---|
| M1 | 底图 Leaflet 1.9.4 + OpenStreetMap 瓦片（unpkg CDN + OSM 免费瓦片，无需 Key）；**演示需联网加载瓦片**，离线时矢量图层（轨迹/事件）仍可显示，页面有降级提示 |
| M2 | 地图中心 (41.80°N, 123.43°E)、缩放 12，覆盖沈阳三环以内 |
| M3 | 轨迹点含经纬度、时间戳、速度三字段；行驶段速度约 8–11 m/s（城市路况），停驶段速度 0 |
| M4 | 绕行几何：在参考路径 entry→exit 之间构造西侧绕行点（三好街一带），用牛顿迭代使绕行段恰好多走指定米数（±1.5 米内），保证种子金额精确 |
| M5 | 等候事件位置取低速段起点；事件定位到参考路径节点表中最近的道路名（≤800 米），超过则记"参考路径沿途" |

## 3. 归因口径

| 编号 | 假设 |
|---|---|
| B1 | 总差额 = 实付 − 预估（可为负）；七个归因项**恒输出**（含 0.00 项） |
| B2 | 等候费只认轨迹可举证的低速段；轨迹缺失时等候费记 0，实付中无法举证的等候部分进入**残差**并标记"待核查"（SY-1005 场景） |
| B3 | 绕路增量只认"偏离参考路径 >50 米的连续段"内多出的里程；拟合度（FIT_BUFFER_M=100、FIT_THRESHOLD=0.8）作为证据保留，但**金额以偏离段米数为准** |
| B4 | 里程费增量 = [运价(实际里程) − 运价(预估里程)] − 绕路增量（同一档位费率），吸收 500 米/455 米取整与 GPS-计费器里程差 |
| B5 | 残差 |r|≤0.01 元归零；>0.01 元必须显示"待核查"（NEEDS_REVIEW），**绝不并入堵车或绕路项凑平** |
| B6 | 一个订单只保留一份最新归因（revision+1）；争议发起时冻结证据快照，重算不影响 |
| B7 | 责任归属仅作叙述分流：绕路→驾驶行为；等候→路况；里程/返空/换档→沈阳固定规则；残差→待核查。系统不裁决 |

## 5. 范围外（明确不做）

真实计价器对接、更准的预估价模型、真实路网路径规划（最短路）、季节/空调判定、登复制权限、支付结算、复杂图表、移动端适配、生产部署。

## 6. 已知局限

1. 锚点坐标为近似值，绕行点在青年大街与三好街之间的"虚拟位置"，不代表真实路口几何。
2. 偏离判定基于直线距离，无法区分封路/禁左等合理绕行；绕路增量定位为"待复核证据"。
3. 参考路径为锚点折线，非真实路网最短路；预估里程由演示数据给定。
4. 等候事件平均速度为 0（演示停驶）；真实蠕行（6 km/h）场景的金额计算相同（按秒数）。
5. 生活化验收样例中等候费 6.00 元（4×180 秒高峰）与绕路增量 3.00 元（1.5 公里）：需求示例的"360 秒 → 4.2 元"与"120 秒/元"高峰费率在算术上不一致（360/120=3.00），本系统按沈阳固定费率给出**规则精确**的数字，结构完全一致（等候费 + 绕路增量 + 残差 0 = 9.00 元）。
