# ASSUMPTIONS.md — 技术假设与边界声明

> 需求未明确处，以本文件与 `config/attribution.yaml` 为准。
> 当前口径：`config_version = cfg-1.0.0`、`algorithm_version = faretrace-attr-1.0.0`（2026-03）

## 0. 数据真实性声明（最重要）

1. 本项目**全部订单、账单、轨迹、参考路径、费率均为合成/模拟数据**（`app/services/seed.py` 生成），不含任何真实平台数据、真实 GPS 轨迹或真实扣款。
2. 系统**不接入真实支付、真实地图/路径规划 API、真实网约车平台接口**；不产生任何真实费用。
3. 定位是订单完成后的**费用差额归因层**（不做"更准确的预估价模型"），只回答"差额由什么构成、证据是什么"。
4. 引用公开调查/报道一律用**哈佛引用格式占位**（`(Author, Year)`），不作为算法输入。

## 1. 技术选型假设（含与建议栈的差异说明）

| 编号 | 假设 | 说明 |
|---|---|---|
| A1 | Python 3.14.4 + FastAPI 0.133 + Uvicorn | 环境实测可用；单进程、同步实现，课程演示规模足够 |
| A2 | SQLAlchemy 2.0（同步 ORM）+ SQLite 单文件 | 免安装数据库服务；不引入 Alembic，模型变更用 `reset_db()` 重建 |
| A3 | Pydantic v2 做入参校验，响应为显式 JSON 字典 | 避免为演示引入多层 DTO；字段契约见 `docs/system-design.md` |
| A4 | **shapely 2.1** 用于轨迹点 → 参考折线投影 | 已实测可用；投影在"局部等距平面"完成，再用 Haversine 复核 |
| A5 | 距离用 Haversine（R=6371 km），坐标 WGS-84 `(lat, lng)` | 城市尺度误差 < 0.5%，无需真实路网 |
| A6 | 金额单位**元**，`Decimal` + `ROUND_HALF_UP` 量化 2 位小数 | 数据库 `Numeric(10,2)`；API 输出 2 位小数字符串，避免浮点歧义 |
| A7 | 阈值/规则全部外置 `config/attribution.yaml`，可经 `GET /api/config` 只读查询 | 代码中无魔法数字；`config_version` 落库到归因记录 |
| A8 | 前端 Jinja2 + 单 CSS + 原生 JS，仅 3 页面 | 无构建工具、无登录/权限、无图表库 |
| A9 | 测试 pytest + 内存/临时 SQLite + `TestClient` | `.db` 文件、`__pycache__` 不入库（见 `.gitignore`） |
| A10 | 时间戳统一 UTC 存库，页面按 `%Y-%m-%d %H:%M` 展示 | 演示城市固定，不做时区换算 UI |

## 2. 金额与守恒

| 编号 | 假设 |
|---|---|
| M1 | `总差额 total_delta = 实付 paid_amount − 预估价 quoted_price`（可为负） |
| M2 | 6 个归因项**永远全部输出**（金额可为 0.00），包括 `UNEXPLAINED_RESIDUAL` |
| M3 | 残差 `residual = total_delta − Σ(其余五项)`；`|residual| ≤ 0.01` 元时归零并注明"舍入容差内归零" |
| M4 | 守恒判定容差 ±0.01 元（`money.epsilon`）；测试与页面均按此断言 |
| M5 | 允许负金额归因项（优惠/更短更快的行程），不做绝对值截断 |
| M6 | `|residual| > 1.00` 元时归因状态置 `NEEDS_REVIEW`（提示人工复核），不自动"凑平" |

## 3. 轨迹与几何

| 编号 | 假设 |
|---|---|
| G1 | 轨迹少于 `MIN_POINTS=3` 个有效点、或时间戳无法构成行驶段 → `data_quality = INCOMPLETE`，降级计算（不崩） |
| G2 | 去重规则：时间戳相同且位置差 ≤ 1 米视为重复点；同位置不同时间戳（停驶）**保留** |
| G3 | 异常点：相邻点隐含速度 > 55.6 m/s（200 km/h）判为异常并剔除，打 `TRAJECTORY_OUTLIERS_REMOVED` |
| G4 | 拟合度 `fit_score = max(0, 1 − 平均偏离距离 / FIT_BUFFER_M)`，默认 `FIT_BUFFER_M=100` m、`FIT_THRESHOLD=0.8`；平均偏离按**全部轨迹点**到参考折线的垂直距离求平均 |
| G5 | 参考路径为折线点集 `[[lat,lng], ...]`，不区分路网/单向限制/禁左，因此"偏离"只是**证据线索**，不等于"绕路事实" |
| G6 | 拥堵判定：连续段速度 < `CONGESTION_SPEED_KMH=15` 且该连续段时长 ≥ `MIN_CONGESTION_SECONDS=60` 时，整段时长计入拥堵；停驶点（速度 0）按同规则归入 |
| G7 | 轨迹缺口（相邻点 > `MAX_GAP_SECONDS=180` 秒）仍可用，但打 `TRAJECTORY_GAP` 并在证据中注明 |

## 4. 归因口径（业务假设，需在报告"方法论"章节说明）

| 编号 | 口径 |
|---|---|
| B1 | **路径偏离**：仅当 `fit_score < FIT_THRESHOLD` 时按 `max(0, ΔD)/1000 × 账单里程单价` 计金额；高拟合度时金额 0，但**仍保留 fit_score 与平均偏离距离证据** |
| B2 | **拥堵延迟**：`拥堵秒数 / 60 × 账单时长单价`（即按分钟计费口径） |
| B3 | **司机或其他延迟**：`max(0, ΔT − 拥堵秒数) / 60 × 账单时长单价`；剩余时长为负时不产生正向金额（保留说明） |
| B4 | **计价规则变化**：`Δ起步价 + Δ里程单价×实际公里 + Δ时长单价×实际分钟 + Δ加价系数×计费基数`，逐字段列出快照值与账单值 |
| B5 | **路侧杂费变化**：`(账单杂费 + 账单其他费用 − 账单优惠) − (快照杂费 − 快照优惠)`，逐条列出差异 |
| B6 | 轨迹缺失时：拥堵金额记 0（`CONGESTION_UNVERIFIED`），正时间偏差全部计入"司机/其他延迟"（降级口径，证据中明示"无法区分拥堵与司机延迟"） |
| B7 | 系统**不做责任裁决**：`impact_class` 只是叙述分流（司机相关 / 路况 / 平台规则 / 无法归因） |
| B8 | 一个订单只保留**一份最新归因**（重算 `revision+1`，同表更新，不删除历史争议引用的记录） |
| B9 | 争议发起瞬间冻结 `evidence_snapshot_json` + `dispute_evidence` 绑定行，之后任何重算都不影响快照 |

## 5. 范围外（明确不做）

- 更准的预估价模型/机器学习、真实路况与路网导航、动态定价的真实业务规则
- 登录/权限/多租户、真实支付退款、发票与结算
- 前端工程化（Vite/React）、复杂图表、移动端适配
- 容器化、CI/CD、微服务拆分、分布式缓存

## 6. 合规与隐私（用于 TELOS 法律可行性章节）

1. 演示数据无个人信息：起点/终点为"某小区/某写字楼"级别标签，无精确住址。
2. 轨迹为合成坐标，不可反推真实位置。
3. 若真实落地：轨迹属个人行踪信息，须最小化留存、加密存储、明示授权，争议举证时对司机/乘客身份脱敏（《个人信息保护法》《数据安全法》）。
4. 账单对乘客与司机双向可见是设计目标；司机侧不暴露乘客手机号等身份信息。

## 7. 已知局限（写入报告"局限与展望"）

1. 偏离判定基于直线距离，无法识别"合理绕行（封路/禁左/单向）"，故 `PATH_DEVIATION` 只能作为待复核证据。
2. 无真实路况，拥堵依赖轨迹速度阈值；短暂停车可能被计入拥堵（已用 60 秒下限 + 连续段降低误判）。
3. 轨迹缺失时的时间归因是降级口径（拥堵置 0、正时长全部计入司机/其他延迟），不代表真实责任。
4. 计价模型仅覆盖：起步价 + 里程 + 时长 + 最低消费 + 加价系数 + 杂费 + 优惠。
5. 单进程 + SQLite，不适用于生产并发；仅课程演示。
